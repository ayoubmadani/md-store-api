# تطبيق المخزون للتاجر (mdstore-stock) — وثيقة التصميم

## الهدف ولماذا

التاجر يريد أن يعرف **ماذا يشتري، ومتى، وكم يربح** — في مكان واحد مخصّص للمخزون، دون أن يبحث داخل لوحة التاجر الكبيرة.

التطبيق **منفصل** (مثل تطبيق التأكيد)، لكنه **تابع لنفس المنصة**: نفس الحساب، نفس المتاجر، نفس الـ API. لوحة التاجر لا تتغيّر — يُضاف لها زر واحد يفتح التطبيق.

## المستخدم

**التاجر نفسه** (وأعضاء فريقه الذين لهم صلاحية المنتجات). ليس تطبيقاً لموظفي مخزن — أدوات المخزن التشغيلية مؤجّلة.

## الدخول

- **زر «المخزون» في لوحة التاجر:** يفتح التطبيق مسجّل الدخول مباشرة على نفس المتجر.
  - آمن: اللوحة تطلب من الـ API **رمزاً لمرة واحدة** صالحاً 60 ثانية، والتطبيق يستبدله بجلسة. لا يمرّ رمز الدخول الحقيقي في الرابط.
- **صفحة دخول مستقلة:** `stock.mdstore.top/login` بالبريد وكلمة السر (نفس دخول اللوحة) — لفتحه مباشرة من الهاتف.
- **اختيار المتجر:** قائمة متاجر التاجر في الأعلى.

## المحتوى (بالأولوية)

### 1. الأساسي — يعتمد على ما بُني في الـ API
- **الرئيسية:** إجمالي القطع، القيمة بسعر البيع والشراء، الربح المتوقع، عدد المنخفض والنافد، آخر الحركات.
- **المخزون:** كل المنتجات ونسخها، الحالة، بحث وفلترة، توريد وجرد، حد التنبيه وسعر الشراء.
- **السجل:** كل دخول وخروج بسببه والطلب ومن قام به، فلتر بالمنتج والتاريخ.
- **التنبيهات:** المنخفض والنافد فقط.

### 2. التقارير — «ماذا أطلب الآن؟»
- لكل منتج/نسخة: **سرعة البيع** (قطع/يوم في آخر 30 يوماً من الطلبات المؤكدة)، **ينفد خلال X يوم**، **الكمية المقترحة** لتغطية 30 يوماً.
- **الأكثر مبيعاً** و**الراكد** (لم يُبع منذ 30 يوماً وفي المخزون).

### 3. الموردون وأوامر الشراء
- **موردون:** الاسم، الهاتف، ملاحظات.
- **أمر شراء:** مورّد، منتجات/نسخ، كميات، سعر شراء لكل وحدة، الحالة (مسودة ← مُرسَل ← مُستلَم جزئياً/كلياً ← ملغى).
- **عند الاستلام:** يُضاف المخزون تلقائياً (حركة «توريد» مربوطة بأمر الشراء)، ويُحدَّث سعر الشراء للمنتج.

### 4. المرتجعات
- طلب «مرتجع» يرجع مخزونه تلقائياً (موجود). يُضاف: **تسجيل قطع تالفة** من المرتجع أو من المخزون (حركة «تالف» تُنقص المخزون وتظهر كخسارة بسعر الشراء).

### مؤجّل
الباركود، جلسات الجرد الكاملة، عدة مخازن.

## ما يُعدّ فشلاً حتى لو اشتغل تقنياً

- رقم مخزون في التطبيق يختلف عن لوحة التاجر أو عن الطلبات.
- استلام أمر شراء مرتين يضيف المخزون مرتين.
- عضو فريق بلا صلاحية المنتجات يرى المخزون أو القيم المالية.

## البناء

- **مشروع جديد `mdstore-stock`:** React + Vite + Tailwind، ثلاث لغات (ar/fr/en)، مصمّم للهاتف أولاً، نفس هوية المنصة.
- **نشر:** Vercel، دومين `stock.mdstore.top`، ريبو GitHub جديد.
- **الـ API (md-store-api) — إضافات فقط:**
  - رمز دخول لمرة واحدة (إنشاء من اللوحة / استبدال من التطبيق).
  - تقارير سرعة البيع والراكد.
  - جداول الموردين وأوامر الشراء وعناصرها + روابطها.
  - سبب حركة جديد «تالف» (`damaged`) و«شراء» (`purchase`).
- **لوحة التاجر:** زر واحد «فتح تطبيق المخزون». صفحة المخزون الحالية تبقى.

## مراحل التسليم

1. التطبيق + الدخول + الأساسي.
2. التقارير.
3. الموردون وأوامر الشراء.
4. التالف.

كل مرحلة تُختبر وتُعرض قبل التي تليها.

## قراراتي (راجعها)

- **رمز لمرة واحدة** بدل وضع رمز الدخول في الرابط (أمان).
- **سرعة البيع** من الطلبات المؤكدة/المشحونة/المسلّمة في آخر 30 يوماً؛ «الكمية المقترحة» لتغطية 30 يوماً.
- **الصلاحية:** نفس صلاحية المنتجات (`product.crud`)؛ القيم المالية تظهر لمن له هذه الصلاحية.
- **الدومين** `stock.mdstore.top` والريبو `mdstore-stock`.
